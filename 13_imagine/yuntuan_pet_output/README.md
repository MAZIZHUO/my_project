## 上一版 WebP 损坏的根因与修复

上一版 `spritesheet.webp` 与 `spritesheet.png` 的**可见（不透明）像素完全一致**，但**全透明像素的 RGB 被编码器改写得面目全非**（1,808,365 个像素 RGB 偏差 > 16）。这正是肉眼看到的“灰色/粉色矩形块、绿色色块、青/黄/白色条纹、扫描线”的来源：这些垃圾 RGB 位于 alpha = 0 区域，正常情况下不可见，但一旦渲染器做缩放/插值、或不严格按 alpha 合成，就会被当成真实颜色显示出来，而 WebP 的分块编码结构使它们呈现为矩形色块。

修复（已实测验证）：

1. **透明像素的 RGB 一律置零** → 最终图集中 alpha = 0 的像素严格为 `RGBA(0,0,0,0)`，编码器没有任何“可优化”的颜色数据可改写。
2. **WebP 使用 `lossless=True, method=0`** → `method=4/6` 会继续在透明区写入垃圾；`method=0` 不会。

实测结果（见 `validation-report.json`）：

| 配置 | 透明区 RGB 偏差 > 16 的像素数 |
|------|------------------------------|
| 保留颜色 + method=4（上一版） | **1,808,365** |
| 保留颜色 + method=0 | 29,740 |
| **置零 + method=0（当前）** | **0** |

当前 WebP 与 PNG 做到**逐像素完全一致**：`WebP RGB exact everywhere`（max diff = 0）、`WebP alpha exact everywhere`（max diff = 0）。

## 处理流程

1. **分析源图** — 定位棋盘格的两个中性灰度级（≈100 与 ≈122）；用近白色行剖面定位 11 条 ROW 标题文字带；据此求出 11 行动画区与 8 列的真实范围。**源图并非标准 192×208 网格，没有被整体缩放。**
2. **严格抠图** — 背景判据为 `饱和度 < 16 且 明度 ∈ [70,150]` 的中性灰。逐格做连通域分析，**只保留面积最大的那一个连通域（萨摩耶本体）**，其余全部丢弃：
   - 文字字符、棋盘格、噪点、扫描线、边界、邻格残留 —— 全部移除
   - 与身体分离的烟雾/泪滴等特效 —— 一并移除（规格要求“只保留连通的萨摩耶本体”）
   - 结果：**每个使用格子里有且只有一只孤立的萨摩耶**
   随后补齐内部空洞，生成真正的 alpha 通道；白色毛发、深色五官、天蓝色围巾均不在背景判据内，不会被误删。
3. **边缘净化** — 透明区 RGB 填充为最近的角色像素色，避免 LANCZOS 重采样把灰色背景拖进轮廓形成灰边。
4. **重采样与对齐** — 每帧按包围盒裁剪后，用**全局统一缩放系数 0.96** 缩放（非逐帧自适应，不破坏角色大小关系），再放入 192 × 208 格子：水平居中；垂直以每行**中位脚底基线**统一映射到格内 y = 200；JUMPING 行的空中帧保留相对抬高量。
5. **补帧（见下）**
6. **收尾** — 清除重采样振铃噪点（alpha < 10 → 0），透明像素 RGB 置零。

## 补帧：不再留空

源图只有 **71** 帧，规格要求 **73** 帧。缺失的 2 帧用**运动补偿插帧**（Horn–Schunck 光流）从同一行的相邻帧重建，而不是复制粘贴：

| 缺失格 | 重建来源 | 说明 |
|--------|---------|------|
| ROW 0 / IDLE / 列 5 | r0c4 + r0c0 | 待机是循环动画，取**回绕**方向 c4 → c0 的中间帧 |
| ROW 8 / REVIEW / 列 5 | r8c4 + r8c0 | 同上 |

- 光流在**已对齐到格子坐标系**的两帧之间计算，因此合成帧天然与同行其他帧共享同一尺寸、同一基线与同一构图。
- 使用预乘 alpha 做形变与混合，边缘不会出现颜色渗漏。
- 回绕插值的合理性已用数据验证：行 0 相邻帧平均差为 6.46 / 6.54 / 4.25 / 5.03，回绕差（c4↔c0）为 **4.06**；行 8 相邻帧差为 7.52 / 4.33 / 5.00 / 4.65，回绕差为 **6.46**。回绕差与相邻帧差同量级，说明序列确实是循环，取回绕中点是正确的补帧位置。
- 合成帧完整保留了同一只萨摩耶的身份、体型、基线、脸型、五官、爪子、白色蓬松毛发与天蓝色围巾。
